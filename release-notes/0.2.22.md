Plan limits now find your Claude Code sign-in exactly the way Claude Code does. This matters if you set `CLAUDE_CONFIG_DIR` or `CLAUDE_SECURESTORAGE_CONFIG_DIR`.

- A custom `CLAUDE_CONFIG_DIR` is matched exactly as you typed it, and folder names with accented letters now work.
- `CLAUDE_SECURESTORAGE_CONFIG_DIR` is followed when set, including when it's set but empty.
- The Keychain is checked first, then the `.credentials.json` file, so an old file can no longer hide a working sign-in.
- The Keychain is asked for your user name along with the item, as Claude Code asks for it, so a copy filed under another name is never picked up.

Thanks to @mattabate for reporting the problem in issue #3, and to @vellumkasane for working out how Claude Code names its Keychain items.
